# ② 核心功能模块源码解析

## 概览

`blog-theme.ts` 中有一批配置项直接决定了博客的交互体验。本文从源码层面拆解五个核心模块的内部实现。

## 1. 推荐阅读（recommend）

### 配置入口

```typescript
recommend: {
  title: '📌 推荐阅读',
  nextText: '下一组',
  pageSize: 5,
  style: 'card'    // "card" | "sidebar" | undefined
}
```

### 源码实现逻辑

推荐阅读模块在主题内部是一组 Vue 组件，位于 `@sugarat/theme/client/components/Recommend*.vue`。

**工作原理**：

```
用户配置
  → getThemeConfig() 将 recommend 存入 themeConfig
  → 运行时 BlogLayout.vue 读取 themeConfig.recommend
  → RecommendContainer.vue 根据 style 选择渲染方式
  → RecommendCard.vue / RecommendSidebar.vue 渲染内容
```

**推荐算法**（伪代码）：

```typescript
function getRecommendedArticles(allArticles, currentArticle, pageSize) {
  // 1. 排除当前文章
  const candidates = allArticles.filter(a => a.route !== currentArticle.route)
  
  // 2. 按标签相似度排序
  candidates.sort((a, b) => {
    const aScore = tagOverlap(a.tags, currentArticle.tags)
    const bScore = tagOverlap(b.tags, currentArticle.tags)
    return bScore - aScore
  })
  
  // 3. 取前 pageSize 篇
  return shuffle(candidates.slice(0, pageSize))
}
```

关键点：
- **基于标签匹配**：与当前文章标签重叠越多，推荐优先级越高
- **随机打底**：如果标签匹配的文章不足，用随机文章补齐
- **"下一组"**：点击 `nextText` 按钮时触发重新随机

### style 模式对比

| style | 渲染位置 | 样式 | 移动端适配 |
|-------|---------|------|-----------|
| `'card'` | 文章末尾 | 卡片网格 | 单列堆叠 |
| `'sidebar'` | 侧边栏 | 列表推荐 | 折叠 |
| `undefined` | 隐藏 | - | - |

## 2. 精选文章（hotArticle）

### 配置入口

```typescript
hotArticle: {
  title: '🔥 精选文章',
  nextText: '换一组',
  pageSize: 9,
}
```

### 实现原理

精选文章是首页专属组件，渲染在首页 hero 区域下方。

源码中，`HotArticle.vue` 的实现：

```typescript
// 伪代码示意
const allArticles = usePagesData()
const hotArticles = computed(() => {
  // 从所有文章中筛选标记为 hot 的文章
  return allArticles.value
    .filter(article => article.meta?.top || article.meta?.hot)
    .slice(0, pageSize)
})
```

**精选文章的两种标记方式**：

1. **Frontmatter 标记**：在文章 `.md` 文件中设置
   ```yaml
   ---
   top: true      # 置顶
   hot: true      # 热门（精选）
   ---
   ```

2. **自动选取**：如果没有手动标记的文章，主题会按时间倒序 + 阅读量排序取前 `pageSize` 篇

### 与 recommend 的对比

| 特性 | recommend | hotArticle |
|------|-----------|------------|
| 显示位置 | 文章页底部/侧边栏 | 首页 |
| 选取方式 | 标签相似度 + 随机 | 手动标记 + 自动 |
| 交互 | 下一组（随机刷新） | 换一组（随机刷新） |
| pageSize 默认值 | 5 | 9 |

## 3. 首页标签（homeTags）

### 配置入口

```typescript
homeTags: {
  title: '🏷 标签',
  limit: 20,
  showCount: true,
  sort: 'desc',
}
```

### 源码实现

标签云组件在 `@sugarat/theme/client/components/HomeTags.vue` 中。

**核心逻辑**：

```typescript
const tagMap = new Map<string, number>()

// 遍历所有文章，统计每个标签的出现次数
allArticles.forEach(article => {
  const tags = article.meta?.tag || []
  tags.forEach(tag => {
    tagMap.set(tag, (tagMap.get(tag) || 0) + 1)
  })
})

// 排序
const sortedTags = [...tagMap.entries()]
  .sort((a, b) => sort === 'desc' ? b[1] - a[1] : a[1] - b[1])

// 截取 limit
const displayTags = sortedTags.slice(0, limit)
```

**limit 的实现**：超出 `limit` 的部分会折叠，通过一个"展开/收起"按钮控制。

### 标签的"数据来源"

标签数据完全来自 Markdown 文件中的 Frontmatter：

```yaml
---
tag:
  - Vue
  - TypeScript
  - 前端
---
```

主题在构建时通过 `createContentLoader` 收集所有页面的 Frontmatter，生成 `pagesData`。

## 4. 搜索（search）

### 配置入口

```typescript
search: {
  btnPlaceholder: '搜索',
  placeholder: '搜索文章...',
  emptyText: '没有找到相关内容',
  heading: '共 {{searchResult}} 条搜索结果',
},
// 或 search: false 关闭搜索
```

### 底层方案：pagefind

sugar-blog 默认使用 [pagefind](https://pagefind.app/) 实现离线全文搜索。这是**构建时索引 + 运行时检索**的方案。

**构建时**（Node.js 端）：

```
vitepress build
  → pagefind 扫描构建产物（HTML 文件）
  → 提取文本内容，构建倒排索引
  → 生成搜索索引文件（pagefind 文件夹）
```

**运行时**（浏览器端）：

```typescript
// 用户点击搜索按钮
→ 加载 pagefind UI 组件
→ pagefind 在浏览器中加载索引分片
→ 用户输入关键词 → 在索引中检索 → 返回结果
```

### 自定义与备选

如果设置 `search: false`，主题不会加载 pagefind。你可以接入其他搜索方案：
- [Algolia DocSearch](https://docsearch.algolia.com/)（需要提交申请）
- [Lunr.js](https://lunrjs.com/)（浏览器端索引）
- [minisearch](https://github.com/lucaong/minisearch)（轻量全文搜索）

## 5. 评论系统（comment）

### 配置入口

```typescript
comment: {
  type: 'giscus',
  options: {
    repo: 'yangshuyin98/my-tech-blog',
    repoId: 'R_kgDOSaDZJw',
    category: 'Announcements',
    categoryId: 'DIC_kwDOSaDZJ84C8xHF',
  }
}
```

### 多后端架构

主题内部实现了一个**评论适配器模式**：

```typescript
// 伪代码
interface CommentAdapter {
  name: string
  mount(el: HTMLElement, options: Record<string, any>): void
  unmount(): void
}

const adapters: Record<string, CommentAdapter> = {
  giscus: GiscusAdapter,
  waline: WalineAdapter,
  twikoo: TwikooAdapter,
  // ...
}

function mountComment(config) {
  const adapter = adapters[config.type]
  if (adapter) {
    adapter.mount(commentContainer, config.options)
  }
}
```

**目前支持的评论后端**：

| type | 后端 | 数据存储 | 是否需要 OAuth |
|------|------|---------|---------------|
| giscus | GitHub Discussions | GitHub | ✅ |
| waline | LeanCloud | 自建 | ❌ |
| twikoo | 腾讯云/自托管 | 云函数 | ❌ |

### Giscus 深度解析

从 `blog-theme.ts` 中的配置可以看到 Giscus 需要 4 个参数，获取方式：

1. 安装 [Giscus App](https://github.com/apps/giscus) 到你的仓库
2. 选择你的仓库
3. 选择 Discussions 分类（Announcements / General 等）
4. 页面自动生成 repoId、categoryId

Giscus 的工作流程：

```
页面加载评论组件
  → 初始化 Giscus SDK（从 cdn 加载 iframe）
  → iframe 连接 GitHub Discussions API
  → 根据页面 URL 匹配对应 Discussion
  → 展示已有评论 / 允许新评论
```

## 小结

五个核心模块的实现思路各有不同：

| 模块 | 实现范式 | 执行阶段 |
|------|---------|---------|
| recommend | Vue 组件 + 随机算法 | 运行时 |
| hotArticle | Frontmatter 标记 + 排序 | 编译时+运行时 |
| homeTags | 数据聚合 + 标签云渲染 | 编译时+运行时 |
| search | pagefind 构建时索引 | 编译时+运行时 |
| comment | 适配器模式 + 第三方 SDK | 运行时 |

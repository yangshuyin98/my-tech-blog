# ④ 从阅读源码到二次开发

## 概述

前三篇文章我们深入了 sugar-blog 的源码架构。本文将这些知识整合，讲解如何从"使用者"变成"贡献者"——fork 主题、自定义 Layout、扩展功能、提交 PR。

## 方案对比：扩展 vs Fork vs 重写

在开始之前，先明确三种路线的选择：

| 方案 | 适合场景 | 维护成本 | 优点 | 缺点 |
|------|---------|---------|------|------|
| **扩展** | 只需添加组件/样式 | 低 | 保留上游更新 | 无法修改核心逻辑 |
| **Fork** | 需要修改主题核心逻辑 | 中 | 完全控制 | 需要手动同步上游 |
| **重写** | 需要完全不同的设计 | 高 | 不受限 | 从头搭建 |

### 扩展：利用主题已有的扩展点

对大部分需求，主题已经预留了扩展点：

```typescript
// theme/index.ts — 组件注册
// user-theme.css — 样式覆盖
// config.mts — 配置覆盖
```

如果你只是想加个组件、改个颜色、换个布局——**不要 Fork，直接扩展**。

### Fork：什么时候需要

当你需要修改主题的**核心组件**时，才考虑 Fork：

```bash
# Fork 仓库后
git clone https://github.com/你的用户名/theme.git
cd theme
npm install
```

需要 Fork 的场景：
- 修改文章页的布局结构（移动 TOC 位置、调整正文宽度）
- 修改首页布局（更换 hero 区域渲染方式）
- 添加构建步骤（自定义数据源转换）

## 2. 自定义 Layout 实战

### 为什么需要自定义 Layout

sugar-blog 提供了默认的博客布局，但你可以在 `theme/index.ts` 中覆盖它。

### 实现步骤

**第一步：在 `theme/` 下创建你的 Layout**

```vue
<!-- docs/.vitepress/theme/MyLayout.vue -->
<script setup lang="ts">
import DefaultLayout from '@sugarat/theme/Layout.vue'
// 或者：从 vitepress 默认主题导入
// import DefaultTheme from 'vitepress/theme'
</script>

<template>
  <div class="my-custom-wrapper">
    <!-- 在博客内容上方加一个全局横幅 -->
    <div class="global-banner">📢 公告区域</div>
    
    <!-- 复用主题的默认 Layout -->
    <DefaultLayout />
    
    <!-- 在页脚下方加自定义内容 -->
    <div class="custom-footer">
      Powered by My Custom Sugar-Blog
    </div>
  </div>
</template>

<style scoped>
.global-banner {
  background: linear-gradient(135deg, #667eea 0%, #764ba2 100%);
  color: white;
  text-align: center;
  padding: 8px;
  font-size: 14px;
}
</style>
```

**第二步：在 `theme/index.ts` 中覆盖 Layout**

```typescript
// docs/.vitepress/theme/index.ts
import BlogTheme from '@sugarat/theme'
import MyLayout from './MyLayout.vue'

export default {
  ...BlogTheme,
  Layout: MyLayout,     // ← 这里覆盖 Layout
  enhanceApp(ctx) {
    BlogTheme.enhanceApp?.(ctx)
  }
}
```

### 布局插槽（Slots）

VitePress 的 Layout 组件提供了多个插槽：

```vue
<template>
  <DefaultLayout>
    <template #nav-bar-title-before>
      <!-- 导航栏标题前 -->
    </template>
    <template #nav-bar-content-after>
      <!-- 导航栏内容后 -->
    </template>
    <template #sidebar-nav-before>
      <!-- 侧边栏顶部 -->
    </template>
    <template #aside-top>
      <!-- 右侧面板顶部 -->
    </template>
    <template #aside-bottom>
      <!-- 右侧面板底部 -->
    </template>
    <template #doc-before>
      <!-- 文档内容前 -->
    </template>
    <template #doc-after>
      <!-- 文档内容后 -->
    </template>
  </DefaultLayout>
</template>
```

这些插槽名需要查看 VitePress 源码中的 `Layout.vue` 来确认。

## 3. Hook 构建流程

### 主题提供的构建钩子

在 `getThemeConfig` 中，主题内置了几个构建流程钩子：

```typescript
// 1. RSS 生成（构建后）
// buildEnd hook 中生成 RSS XML 文件

// 2. search 索引构建（构建后）
// pagefind 在 buildEnd 后运行

// 3. pagesData 收集（构建中）
// createContentLoader 在 build 时收集所有页面 frontmatter
```

### 自定义构建插件

如果你想在构建完成后执行自定义操作，可以通过 VitePress 的 `buildEnd` 钩子：

```typescript
// config.mts
export default defineConfig({
  extends: blogTheme,
  // ...
  buildEnd(siteConfig) {
    // 构建完成后执行
    console.log('Build finished!')
    
    // 例如：生成 sitemap
    // 例如：压缩图片
    // 例如：发送通知
  }
})
```

### 扩展 Markdown 解析

```typescript
// config.mts — 通过 markdown 配置扩展
export default defineConfig({
  extends: blogTheme,
  markdown: {
    config(md) {
      // 添加 markdown-it 插件
      md.use(require('markdown-it-footnote'))
      
      // 自定义渲染规则
      const defaultRender = md.renderer.rules.image
      md.renderer.rules.image = (tokens, idx, options, env, self) => {
        // 给所有图片添加懒加载
        const token = tokens[idx]
        token.attrSet('loading', 'lazy')
        return defaultRender(tokens, idx, options, env, self)
      }
    }
  }
})
```

## 5. 如何向主题提交 PR

如果你修改了主题并想贡献回社区：

### 准备工作

```bash
# 1. Fork 仓库
# 2. 克隆到本地
git clone https://github.com/你的用户名/theme.git
cd theme

# 3. 查看 issue 和贡献指南
# 通常仓库根目录有 CONTRIBUTING.md
```

### PR 建议

| 类型 | 怎么做 | 示例 |
|------|-------|------|
| Bug fix | 写测试用例，说明复现步骤 | 修复某个组件在特定条件下的样式异常 |
| 新功能 | 先开 issue 讨论，避免重复工作 | 添加新的评论后端 |
| 文档 | 修复 typo，补充缺失说明 | 完善某个配置项的文档 |

### PR Checklist

- [ ] 代码风格一致（ESLint / Prettier）
- [ ] 新增功能有对应的文档
- [ ] 不破坏现有配置的向后兼容
- [ ] 如果是 UI 改动，附上截图对比
- [ ] Commit message 遵循 Conventional Commits

## 6. 从阅读到产出：一个完整示例

我们完整走一遍：**添加一个"阅读量统计"徽标**。

### 需求

在文章页顶部显示"👁️ xxx 次阅读"。

### 方案评估

| 方案 | 说明 | 选择 |
|------|------|------|
| 不用 Fork | 在 `enhanceApp` 中注入 | ✅ |
| Fork 主题 | 修改主题核心组件 | ❌ 杀鸡用牛刀 |

### 实现

```typescript
// docs/.vitepress/theme/index.ts
import BlogTheme from '@sugarat/theme'
import { inBrowser } from 'vitepress'

export default {
  ...BlogTheme,
  enhanceApp(ctx) {
    BlogTheme.enhanceApp?.(ctx)
    
    if (inBrowser) {
      // 路由切换时更新阅读量
      ctx.router.afterEach((to) => {
        const key = `pageview-${to.path}`
        const count = parseInt(localStorage.getItem(key) || '0') + 1
        localStorage.setItem(key, count.toString())
        
        // 查找页面上的标题区域，添加阅读量显示
        // 注意：需要等待 DOM 渲染完成
        setTimeout(() => {
          const titleEl = document.querySelector('.page-title')
          if (titleEl && !titleEl.querySelector('.pageview-badge')) {
            const badge = document.createElement('span')
            badge.className = 'pageview-badge'
            badge.textContent = `👁️ ${count} 次阅读`
            titleEl.appendChild(badge)
          }
        }, 100)
      })
    }
  }
}
```

# ③ 主题定制与扩展机制

## 概述

sugar-blog 的设计哲学是"**约定优于配置，但配置不够时可以扩展**"。本文从源码层面拆解主题的定制与扩展机制，包括 CSS 变量系统、组件注册、以及友链、公告等特殊模块。

## 1. CSS 变量系统——主题的外壳

### 三层变量结构

sugar-blog 的 CSS 变量设计分为三层：

```
VitePress 默认变量（vp-c-brand-1 等）
  └── sugar-blog 主题变量（扩展、覆盖）
       └── 用户自定义变量（user-theme.css 覆盖）
```

在 `user-theme.css` 中我们看到：

```css
/* 浅色模式 */
html[theme] {
  --vp-c-user-1: red;
  --vp-c-user-2: blue;
  --vp-c-user-3: green;
  --vp-c-user-soft: rgba(255,0,0,.5);
}

/* 深色模式 */
html[theme].dark {
  --vp-c-user-1: yellow;
  --vp-c-user-2: purple;
  --vp-c-user-3: orange;
  --vp-c-user-soft: rgba(255,255,0,.5);
}

/* 覆盖默认品牌色 */
html[theme], html[theme].dark {
  --vp-c-brand-1: var(--vp-c-user-1);
  --vp-c-brand-2: var(--vp-c-user-2);
  --vp-c-brand-3: var(--vp-c-user-3);
  --vp-c-brand-soft: var(--vp-c-user-soft);
}
```

### 变量命名约定

主题遵循 VitePress 的 CSS 变量命名规范：

```
--vp-{组件}-{属性}-{序号}
```

| 类别 | 变量模式 | 示例 |
|------|---------|------|
| 品牌色 | `--vp-c-brand-{1/2/3}` | 主色、悬停色、激活色 |
| 背景色 | `--vp-c-bg` | 页面背景、软背景 |
| 文字色 | `--vp-c-text-{1/2/3}` | 主文字、次要、禁用 |
| 边框色 | `--vp-c-divider` | 分割线、边框 |
| 用户色 | `--vp-c-user-{1/2/3}` | 用户自定义品牌色 |

### themeColor 预设

除了手动写 CSS 变量，主题还提供了 `themeColor` 预设：

```typescript
themeColor: 'el-blue'
```

主题内置了多套预设（从 `@sugarat/theme` 源码的 `presetColors` 中查看）：

```typescript
const presetColors = {
  'el-blue':     { '--vp-c-brand-1': '#409eff', /* ... */ },
  'vp-green':    { '--vp-c-brand-1': '#3eaf7c', /* ... */ },
  'sugar-pink':  { '--vp-c-brand-1': '#fb7299', /* ... */ },
  // ...
}
```

当 `themeColor` 设置后，`getThemeConfig` 会注入对应的 CSS 变量到 VitePress 的 `head` 中：

```typescript
// 伪代码
if (config.themeColor && presetColors[config.themeColor]) {
  const vars = presetColors[config.themeColor]
  const styleContent = Object.entries(vars)
    .map(([k, v]) => `${k}: ${v};`)
    .join('')
  
  head.push([
    'style',
    { id: 'theme-color-vars' },
    `:root { ${styleContent} }`
  ])
}
```

## 2. 组件注册机制——主题的扩展点

在 `theme/index.ts` 中我们看到：

```typescript
export default {
  ...BlogTheme,
  enhanceApp(ctx) {
    BlogTheme.enhanceApp?.(ctx)
    ctx.app.component('Archives', Archives)
  }
}
```

### extends 继承模式

`...BlogTheme` 是**对象展开继承**——把主题默认的所有属性和方法展开到新对象中。然后覆盖 `enhanceApp` 方法。

这里的关键是 `BlogTheme.enhanceApp?.(ctx)`：

- `?` 是可选链——如果主题没有定义 `enhanceApp`，不会报错
- 先调用主题原生的 `enhanceApp`（让主题默认的组件注册、插件生效）
- 再执行你自己的注册逻辑

### 注册自定义组件的流程

```typescript
// 1. 定义组件（Archives.vue）
// 2. 在 theme/index.ts 中注册
ctx.app.component('Archives', Archives)
// 3. 在 Markdown 中使用
<Archives />
```

### 可以自定义的更多扩展点

除了注册组件，`enhanceApp` 中还可以：

```typescript
enhanceApp(ctx) {
  BlogTheme.enhanceApp?.(ctx)
  
  // 注册全局组件
  ctx.app.component('MyComponent', MyComponent)
  
  // 注册全局指令
  ctx.app.directive('focus', { mounted(el) { el.focus() } })
  
  // 注册路由守卫
  ctx.router.beforeEach((to, from) => { /* ... */ })
  
  // 注入全局属性
  ctx.app.config.globalProperties.$myMethod = () => {}
}
```

## 3. 友链模块（friend）

### 配置入口

```typescript
friend: [
  {
    nickname: '粥里有勺糖',
    des: '你的指尖用于改变世界的力量',
    avatar: 'https://...',
    url: 'https://sugarat.top',
  },

```

### 源码实现

友链渲染为**首页底部的小卡片网格**。内部实现：

```typescript
// FriendLink.vue (伪代码)
interface FriendLink {
  nickname: string
  des: string
  avatar: string
  url: string
}

// 从 themeConfig 中读取
const friends = computed(() => theme.value.friend || [])

// 渲染：每个 friend 显示为一张小卡片
// 包含头像、昵称、描述，点击跳转 url
```

友链本身没有复杂的逻辑，但它的设计体现了主题的**数据驱动**思想——纯配置驱动 UI 渲染。

## 4. 公告弹窗（popover）

### 配置入口

```typescript
popover: {
  title: '公告',
  body: [
    { type: 'text', content: '👇公众号👇---👇 微信 👇' },
    { type: 'image', src: '/weixin.png', alt: '杨树银微信二维码' },
    { type: 'button', content: '加群交流', link: '#' },
  ],
  duration: 0   // 关闭弹窗后，多长时间内不再显示（单位：分钟，0=每次都显示）
}
```

### 源码设计——声明式 UI

公告弹窗的实现很有意思，body 是一个**声明式 UI 描述**：

```typescript
type PopoverBodyItem = 
  | { type: 'text';    content: string; style?: string }
  | { type: 'image';   src: string; alt?: string }
  | { type: 'button';  content: string; link: string; props?: Record<string, any> }
```

主题内部对应解析渲染：

```typescript
// Popover.vue
function renderItem(item: PopoverBodyItem) {
  switch (item.type) {
    case 'text':
      return <p style={item.style}>{item.content}</p>
    case 'image':
      return <img src={item.src} alt={item.alt} />
    case 'button':
      return <Button {...item.props} onClick={() => navigate(item.link)}>
        {item.content}
      </Button>
  }
}
```

这种模式的优势：
- **纯配置**：无需写 HTML，只需声明数据
- **类型安全**：TypeScript 接口保证 body 结构正确
- **易扩展**：添加新 type 只需新增 case

### duration 的存储机制

```typescript
// 用户关闭弹窗时
function onClose() {
  if (duration > 0) {
    // 将当前时间戳存入 localStorage
    localStorage.setItem('popover-closed-at', Date.now().toString())
  }
  isVisible.value = false
}

// 下次打开页面时
function shouldShow() {
  const lastClosed = localStorage.getItem('popover-closed-at')
  if (!lastClosed) return true
  
  const elapsed = Date.now() - parseInt(lastClosed)
  return elapsed > duration * 60 * 1000
}
```

## 5. 页脚自定义（footer）

### 配置入口

```typescript
footer: {
  message: '下面 的内容和图标都是可以修改的噢',
  copyright: 'MIT License | shuyin',
  icpRecord: { name: '豫ICP备19011724号', link: 'https://beian.miit.gov.cn/' },
  securityRecord: { name: '公网安备xxxxx', link: 'https://www.beian.gov.cn/' },
}
```

### 实现原理

```typescript
// Footer.vue (伪代码)
// message 和 copyright 直接渲染
// icpRecord 和 securityRecord 只在配置时显示

<!-- 页脚渲染 -->
<div class="footer">
  <p v-if="message" v-html="message"></p>
  <p v-if="copyright">{{ copyright }}</p>
  <p v-if="icpRecord">
    <a :href="icpRecord.link">{{ icpRecord.name }}</a>
  </p>
  <p v-if="securityRecord">
    <a :href="securityRecord.link">{{ securityRecord.name }}</a>
  </p>
</div>
```

注意 `message` 支持 HTML 内容，但需要谨慎使用——会带来 XSS 风险。

## 小结

通过本文你应该理解了：

1. CSS 变量三层覆盖体系——VitePress 默认 → 主题预设 → 用户自定义
2. `enhanceApp` 的链式调用——先执行主题逻辑，再执行用户逻辑
3. 友链是纯数据驱动的卡片渲染，公告弹窗用声明式 UI 描述
4. `popover.duration` 利用 localStorage 实现弹窗频率控制

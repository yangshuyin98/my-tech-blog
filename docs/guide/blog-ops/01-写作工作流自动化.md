# 写作工作流自动化

## 为什么需要自动化工作流？

当你只有三五篇文章时，手动操作没问题。但当博客积累到 50+、100+ 篇文章时，以下场景会频繁出现：

- 新建文章时要手动写 frontmatter（日期、标签、分类）
- 图片需要手动压缩、调整尺寸
- 文章写完后要手动检查格式、更新侧边栏
- 发布前要手动构建验证

本篇文章教你搭建一条**从 Markdown 到自动发布**的全自动化流水线。

## 1. 自动生成 Frontmatter

### 方案一：VSCode Snippet

在 `.vscode/blog.code-snippets` 中创建：

```json
{
  "Blog Post Frontmatter": {
    "scope": "markdown",
    "prefix": "blogpost",
    "body": [
      "---",
      "title: ${1:文章标题}",
      "date: $CURRENT_YEAR-$CURRENT_MONTH-$CURRENT_DATE",
      "icon: ${2:icon-name}",
      "order: ${3:0}",
      "tags: [${4}]",
      "---",
      "",
      "# ${1:文章标题}",
      "",
      "${5}"
    ],
    "description": "生成博客文章的 frontmatter 模板"
  }
}
```

输入 `blogpost` 按 Tab 即可快速插入。

### 方案二：Node.js 脚本一键创建

创建 `scripts/new-post.mjs`：

```javascript
import { writeFileSync } from 'fs'
import { resolve, dirname } from 'path'
import { fileURLToPath } from 'url'

const __dirname = dirname(fileURLToPath(import.meta.url))

const title = process.argv[2]
if (!title) {
  console.error('Usage: node scripts/new-post.mjs "文章标题"')
  process.exit(1)
}

const date = new Date().toISOString().split('T')[0]
const filename = `${date}-${title.replace(/\s+/g, '-')}.md`
const frontmatter = `---
title: ${title}
date: ${date}
icon: note
order: 0
---

# ${title}

`

writeFileSync(resolve(__dirname, `../docs/posts/${filename}`), frontmatter)
console.log(`✓ Created docs/posts/${filename}`)
```

在 `package.json` 添加脚本：

```json
{
  "scripts": {
    "new": "node scripts/new-post.mjs"
  }
}
```

使用：

```bash
npm run new "我的新文章"
```

## 2. 图片自动化处理

### 自动压缩

安装 `sharp`：

```bash
npm install -D sharp
```

创建 `scripts/optimize-images.mjs`：

```javascript
import sharp from 'sharp'
import { readdirSync } from 'fs'
import { resolve, extname, join } from 'path'

const inputDir = resolve('docs/public/images')
const outputDir = resolve('docs/public/images/optimized')

const files = readdirSync(inputDir).filter(f =>
  ['.jpg', '.jpeg', '.png', '.webp'].includes(extname(f).toLowerCase())
)

for (const file of files) {
  await sharp(join(inputDir, file))
    .resize({ width: 1200, withoutEnlargement: true })
    .jpeg({ quality: 80 })
    .toFile(join(outputDir, file.replace(/\.(jpg|jpeg|png)$/, '.webp')))
  console.log(`✓ ${file} → optimized/${file.replace(/\.\w+$/, '.webp')}`)
}
```

### Git Hook 自动优化

创建 `.husky/pre-commit`：

```bash
#!/usr/bin/env sh
. "$(dirname "$0")/_/husky.sh"

# 如果 public/images 有新增图片，自动优化
if git diff --cached --name-only | grep -q "public/images"; then
  node scripts/optimize-images.mjs
  git add docs/public/images/optimized/
fi
```

## 3. 自动生成侧边栏

手动维护侧边栏是痛苦的。用脚本自动生成：

创建 `scripts/generate-sidebar.mjs`：

```javascript
import { readdirSync, readFileSync, statSync } from 'fs'
import { resolve, join } from 'path'

function parseFrontmatter(filePath) {
  const content = readFileSync(filePath, 'utf-8')
  const match = content.match(/^---\n([\s\S]*?)\n---/)
  if (!match) return { order: 999, title: filePath.split('/').pop() }
  const fm = {}
  for (const line of match[1].split('\n')) {
    const [key, ...vals] = line.split(':')
    fm[key.trim()] = vals.join(':').trim()
  }
  return { order: parseInt(fm.order) || 999, title: fm.title || filePath.split('/').pop() }
}

function generateSidebar(dir, prefix = '') {
  const items = readdirSync(dir)
    .filter(f => f.endsWith('.md') && f !== 'index.md')
    .map(f => {
      const filePath = join(dir, f)
      const { order, title } = parseFrontmatter(filePath)
      return { text: title, link: `${prefix}/${f.replace('.md', '')}`, order }
    })
    .sort((a, b) => a.order - b.order)

  // 读取 index.md 作为目录标题
  let folderName = dir.split('/').pop()
  try {
    const indexContent = readFileSync(join(dir, 'index.md'), 'utf-8')
    const { title } = parseFrontmatter(join(dir, 'index.md'))
    folderName = title || folderName
  } catch {}

  return { text: folderName, items }
}

// 生成 docs/guide/ 下所有子目录的侧边栏
const guideDir = resolve('docs/guide')
const sidebar = readdirSync(guideDir)
  .filter(f => statSync(join(guideDir, f)).isDirectory())
  .map(dir => generateSidebar(join(guideDir, dir), `/guide/${dir}`))

console.log(JSON.stringify(sidebar, null, 2))
```

输出结果可以直接粘贴到 `config.mts` 中。

## 4. 自动化发布检查

在 GitHub Actions 中添加检查流程，在 `deploy.yml` 中补充：

```yaml
name: Deploy Blog

on:
  push:
    branches: [master]

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Install dependencies
        run: npm ci

      - name: Lint markdown
        run: npx markdownlint docs/

      - name: Check dead links
        run: npx linkinator docs/ --recurse

      - name: Build
        run: npm run build
```

安装 markdown 检查工具：

```bash
npm install -D markdownlint-cli linkinator
```

添加 `.markdownlint.json`：

```json
{
  "default": true,
  "MD013": false,
  "MD033": false,
  "MD041": false
}
```

## 总结

自动化工作流的意义不在于"炫技"，而在于**减少决策负担**：

- 不要每次想"frontmatter 怎么写"——让脚本帮你写
- 不要每张图手动压缩——交给 hook
- 不要忘记 lint——CI 会拦住你
- 不要手动部署——push 即发布

把写作之外的体力活自动化，你才能专注于唯一重要的事：**写出好文章**。

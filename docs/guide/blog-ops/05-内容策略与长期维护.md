# 内容策略与长期维护

博客最难的不是"搭起来"或"写第一篇"，而是**持续产出**。这篇文章不讲技术，讲如何让你的博客活过三个月。

---

## 1. 内容规划策略

### 1.1 三类内容模型

一个健康的博客应该有三类内容轮动：

```
📌 常青内容（60%）
   └─ 教程、指南、最佳实践（长期有搜索价值）
   
📢 热点内容（20%）
   └─ 新技术体验、版本升级记录（短期流量）
   
📝 个人内容（20%）
   └─ 周报、思考、游记（建立读者连接）
```

- **常青内容**是你博客的根基。一篇好的教程半年后还有人搜到。
- **热点内容**是流量入口。新技术发布时第一时间写体验文。
- **个人内容**是粘性来源。读者看你博客不只是为了技术，更是为了"认识你这个人"。

### 1.2 内容日历

不要等"灵感来了再写"。建立一个简单的内容日历：

```markdown
# 内容日历（示例）

## 4月
- [x] 第1周：VitePress 部署教程（常青）
- [x] 第2周：Vue 3.5 新特性尝鲜（热点）
- [ ] 第3周：我的开发环境配置（个人）
- [ ] 第4周：CSS Grid 完全指南（常青）

## 5月
- [ ] 第1周：...
```

### 1.3 选题评估矩阵

拿不定主意写什么时，用这个矩阵打分：

| 选题 | 读者价值(1-5) | 搜索量(1-5) | 写作难度(1-5) | 总分 |
|------|-------------|-----------|-------------|------|
| Vue 3 迁移指南 | 5 | 4 | 3 | **12** |
| 这周买了啥 | 2 | 1 | 1 | **4** |
| 博客搭建教程 | 4 | 5 | 2 | **11** |

优先选**总分高且写作难度低**的选题——先用简单的积累信心。

## 2. 文章版本管理

### 2.1 更新旧文章

技术文章很容易过时。建立一个更新机制：

在文章 frontmatter 中添加 `updated` 字段：

```yaml
---
title: 文章标题
date: 2024-01-15
updated: 2024-06-20
status: updated
---
```

在页面中显示更新提示：

```vue
<template>
  <div v-if="page.frontmatter.updated" class="update-notice">
    📅 本文于 {{ page.frontmatter.updated }} 更新
  </div>
</template>
```

### 2.2 版本日志

在博客中建立 `changelog` 页面：

```markdown
---
title: 更新日志
icon: log
---

## 2024-06-20

- 📝 更新《VitePress 部署教程》— 新增 GitHub Actions 新语法
- ✏️ 修正《CSS Grid 指南》中的错误示例
- ➕ 新增一篇《Nuxt 3 入门》

## 2024-06-15

- 🎉 博客上线
- 📝 首发 3 篇文章
```

### 2.3 Git 提交规范

用清晰的前缀管理文章的提交历史：

```
feat(posts): 新增《VitePress 部署教程》
fix(posts): 修正 CSS Grid 文章中的代码错误
update(posts): 更新 Vue 3 迁移指南内容
style(blog): 调整首页布局
chore(deps): 升级 VitePress 到 2.0
```

在博客页脚添加 GitHub 提交链接，让读者可以看到文章的历史变更：

```vue
<template>
  <a :href="editLink" target="_blank" class="history-link">
    📜 查看编辑历史
  </a>
</template>

<script setup>
import { useData } from 'vitepress'
const { page } = useData()
const editLink = computed(() =>
  `https://github.com/yangshuyin98/my-tech-blog/commits/master/${page.value.filePath}`
)
</script>
```

## 3. 备份策略

### 3.1 自动备份

GitHub 本身就是最好的备份。但人算不如天算——仓库可能被删、账号可能被封。

#### 方案一：多远程仓库

```bash
# 同时推送到 GitHub 和 Gitee
git remote add github https://github.com/你的用户名/你的仓库.git
git remote add gitee https://gitee.com/你的用户名/你的仓库.git

# 一键推送所有远程
git push --all github master
git push --all gitee master
```

设置一个 alias：

```bash
git config --global alias.pushall '!git push github master && git push gitee master'
```

#### 方案二：自动备份到云盘

使用 GitHub Actions 定期备份到阿里云 OSS 或 S3：

```yaml
# .github/workflows/backup.yml
name: Auto Backup

on:
  schedule:
    - cron: '0 2 * * 0'  # 每周日凌晨2点
  workflow_dispatch:      # 可手动触发

jobs:
  backup:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Bundle blog content
        run: |
          tar -czf blog-backup-$(date +%Y%m%d).tar.gz \
            docs/ package.json pnpm-lock.yaml config.mts

      - name: Upload to OSS
        uses: manyuanrong/oss-action@v3
        with:
          access-key-id: ${{ secrets.OSS_ACCESS_KEY }}
          access-key-secret: ${{ secrets.OSS_SECRET_KEY }}
          bucket: 你的bucket名称
          endpoint: oss-cn-hangzhou.aliyuncs.com
          local-path: ./blog-backup-*.tar.gz
          remote-path: /backups/
```

### 3.2 手动备份清单

除了自动备份，建议每季度做一次手动备份：

- [ ] 导出 GitHub 仓库完整备份（Settings → 导入导出）
- [ ] 下载所有文章 Markdown 源文件
- [ ] 备份图片资源（`docs/public/images/`）
- [ ] 导出评论数据（Giscus/Waline 后台）
- [ ] 导出统计配置（Umami/百度统计设置导出）

## 4. 内容审核与清理

### 4.1 定期审核清单

每季度检查一次：

```
□ 死链检查：链接是否还打得开？
□ 截图更新：教程里的截图是否过时？
□ 版本更新：教程中的工具版本是否更新？
□ 标签整理：标签是否太多太散？
□ 分类调整：文章分类是否还合理？
□ 404 检查：是否有被删除但被引用的页面？
```

### 4.2 使用工具自动化

```bash
# 死链检查
npx linkinator docs/ --recurse

# 过期域名检查
npx broken-link-checker https://你的域名.com

# Markdown 质量检查
npx markdownlint docs/
```

## 5. 读者互动与增长

### 5.1 在文章中埋 Call to Action

```markdown
---

**如果这篇文章对你有帮助：**

- ⭐ [在 GitHub 给博客点个 Star](../README.md)
- 📮 订阅 RSS：`https://你的域名.com/feed.xml`
- 💬 欢迎在评论区留言讨论
```

### 5.2 交叉引用

在文章结尾推荐相关文章：

```markdown
---

## 相关阅读

- 📖 [SEO 全面优化](./02-SEO-全面优化) — 让文章被更多人看到
- 🔧 [写作工作流自动化](./01-写作工作流自动化) — 提升写作效率
- 💬 [评论系统深度集成](./03-评论系统深度集成) — 搭建读者交流渠道
```

### 5.3 跟踪读者反馈

记录读者反馈的渠道：

- GitHub Issues → 技术问题、Bug 反馈
- 评论区 → 讨论、建议
- 邮件 → 深度沟通
- RSS 订阅数 → 内容受欢迎程度

## 6. 技术债务管理

### 6.1 依赖升级策略

```bash
# 每月检查依赖更新
npm outdated

# 更新依赖
npm update

# 大版本升级时需要重点关注：
# - VitePress 升级：检查 breaking changes
# - sugar-blog 升级：查看 changelog
# - Node.js 版本：确认 CI 环境
```

### 6.2 迁移预案

假设有一天需要从 VitePress 迁移到其他框架（Astro、Next.js 等）：

1. **内容与展示分离**：用纯 Markdown 写作，不使用框架特定的语法
2. **结构标准化**：统一的 frontmatter 格式
3. **图片路径规范**：使用相对路径，不用框架内置的图片优化

保持内容的"可移植性"，框架只是工具，内容才是资产。

## 总结：一个博客的成长周期

```
第1个月  🎉 热情期
  写什么都兴奋，一天能写两篇

第2-3月 📉 倦怠期
  开始觉得没东西可写，更新频率下降
  → 关键：建立内容日历，设定最低更新频率

第4-6月 ⚖️ 平稳期
  找到自己的写作节奏
  → 关键：关注数据，知道读者想看什么

第7-12月 📈 增长期
  旧文章开始带来持续流量
  → 关键：更新旧文章，维护内容质量

第2年+   🌱 成熟期
  博客成为你的数字花园
  → 关键：享受写作本身
```

**坚持写下去，比写什么更重要。**
